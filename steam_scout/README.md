# 🎯 Steam 市场侦察兵（SteamScout）

一个 Steam 游戏市场调研 Agent：以聊天窗交互，能联网获取 Steam 实时市场数据，在本地 SQLite 知识库中持续沉淀调研结论、自我进化，回答你的立项问题，评估项目市场潜力，并**基于开发周期与上线时间评估立项时机**。

> 调研种子：B 站 UP 主 [「Gaby学姐说」](https://space.bilibili.com/3546782527130177)（54 期视频，覆盖 Steam 独立游戏市场数据拆解、立项方法论、宣发全流程、爆款案例复盘）。

|---|---|---|---|

> 单文件版**自动探测**本机是否跑着完整版（`127.0.0.1:8792`）：跑着就自动升级为「🔌 完整模式」，没跑就是「📄 单文件模式」。两种模式共用同一个 LLM 配置。

**配置 LLM（两种模式都需要，二选一）**：
1. **网页里填**：单文件版点右上「⚙️ 配置」；完整版点左侧「⚙️ 配置 LLM API」→ 填 Key → 「保存并测试」
2. **编辑 `.env`**：复制 `.env.example` 为 `.env`，填 `DEEPSEEK_API_KEY`

任何 **OpenAI 兼容**服务都行（DeepSeek / OpenAI / 智谱 / 通义 / Kimi / SiliconFlow / 本地 Ollama）。详见 `docs/配置指南.md`。

## 🚀 快速开始（完整版）

**环境要求：仅需 Node.js ≥ 22（无需 npm install）。配置上只需要一个大模型 API Key —— Steam / B站 / 搜索都是公开接口，无需其它 Key。**

```bat
:: 1. 启动（首次打开网页会自动弹出「⚙️ 配置 LLM API」向导，填 Key 即可）
start.bat          :: 或 node server.mjs

:: 2.（可选）命令行方式播种初始调研：B 站 UP 主「Gaby学姐说」全部视频
node src\ingest\seed.mjs
```

打开 **http://127.0.0.1:8792** 即可聊天（端口在 `.env` 的 `PORT` 里改；被占用时 `start.bat` 会自动清理后启动）。

**配置 LLM 的三种方式**（详见 `docs/配置指南.md`）：
1. **网页向导（推荐）**：左侧状态卡「⚙️ 配置 LLM API」→ 填 Key / Base URL / 模型 → 「保存并测试」→ 自动写回 `.env` 并即时生效
2. **编辑 `.env`**：复制 `.env.example` 为 `.env`，填 `DEEPSEEK_API_KEY`（可选改 `LLM_BASE_URL` / `LLM_MODEL`）
3. **环境变量**：`set DEEPSEEK_API_KEY=sk-xxx` 后启动

任何 **OpenAI 兼容**服务都可（DeepSeek / OpenAI / 智谱 / 通义 / Kimi / SiliconFlow / 本地 Ollama）。
未配置 LLM 时仍可用：离线立项评估、数据采集、知识库检索、项目档案、数据盘点。

**可选：接第三方 / 付费数据源**（想要销量/收入/拥有者估算时）
「⚙️ 配置 LLM API」弹窗里展开「🔌 可选：第三方 / 付费数据源」→ 选源 + 填 Key → 「保存并测试数据源」；或直接写 `.env`：

```ini
DATA_PROVIDER=gamalytic          # steamapi(免费) / steamspy(免费) / gamalytic / vginsights / steambase / custom
DATA_PROVIDER_KEY=你的key
DATA_PROVIDER_URL=               # 自定义时填，支持 {appid} / {name}
DATA_PROVIDER_MAP=               # 自定义时填，如 {"owners":"owners","reviews":"reviews.total"}
```

规则很简单：**官方接口优先，缺什么才用你选的源补什么**（价格/好评率/中文支持永远取自 Steam 官方）；
报告首页会写明 `补充数据源 XXX` 并注明哪些字段由它补充；数据源挂了/Key 失效只在过程中提示一行，不阻塞评估。
详见 `docs/配置指南.md`。

> 📚 文档：`SKILL.md` = Agent 能力规格（Claude Skill 格式，可交给其他 Agent 使用）；`AGENTS.md` = 给 AI 编码 Agent 的仓库操作指南；`docs/交互流程.md` = 交互流程与问题排查；`docs/配置指南.md` = LLM 配置与分享说明。

> 未配置 LLM 时：离线立项评估、数据采集、知识库检索仍可用；配置 key 后重启，再跑 `node src\ingest\seed.mjs --distill` 可把原始入库内容升级为提炼观点。

命令行模式（可选）：`node cli.mjs "评估一下XX项目"`（一次性）或 `node cli.mjs`（交互 REPL）。

## 💡 怎么用

**多对话管理**：侧栏「对话」区可**新建对话**、切换或**删除**历史对话（不同项目建议分开聊）；「项目档案」点击项目会**跳转到该项目的评估对话**，每行还有 `📌 结论`（输出该项目评估结论）、`⤓ PDF`（导出报告）、`✕`（删除档案）。

**快捷功能（按步骤）**：侧栏「快捷功能」按使用动线分三步：
- **① 立项评估 · 调研项目**：`📊 评估我的项目` → 填入评估模板（改 XXX 里的项目信息即可）
- **② 看结论 · 深挖竞品**：`📌 输出项目评估结论`（读档案复述结论，不重跑评估）、`🔍 深挖品类与竞品`
- **③ 导出报告**：`⤓ 导出报告 PDF`（前端本地导出，零 token 成本）

所有按钮点击后填入输入框并**自动选中占位符**，改完直接发送。

**立项评估**（消息包含「立项/评估/值不值得做/要多久」自动触发全流程）：

> 我想做一款 2D 像素钓鱼模拟经营游戏，单人开发，有 3 年 Unity 经验，目标 8 个月内上线——值不值得做？市场潜力如何？多久做完最好？

Agent 会自动：识别项目 → 定位 Steam 品类标签 → 拉取新游发行趋势（按年聚合）→ 热销竞品详情（价格/评价/好评率/在线）→ 即将上线竞品数 → 搜索行业趋势 → 检索知识库历史结论 → **出评分报告**（六维评分 + 三档工期 + 窗口评级 + 建议路线 + 风险预案），最后给出专家解读。

**市场调研**（任意聊天问题）：如「2026 年哪些品类在上升期？」「幸存者like 还能进场吗？」「Friendslop 为什么 2 天卖 100 万又快速降温？」——Agent 自主调用工具多轮收集后回答。

**持续监控**：每天自动复盘（Steam 热销榜变动、行业新闻、UP 主新视频入库），复盘报告写入知识库；也可以点侧栏「🔄 立即市场复盘」。

## 📐 评估方法论

**市场潜力评分（0-100 → S/A/B/C/D）**

| 维度 | 权重 | 数据来源 |
|---|---|---|
| 需求规模 | 25% | 头部竞品评价数（销量≈评价数×35）、24h 在线峰值 |
| 竞争强度* | 20% | 近两年同品类新游密度、头部集中度、即将上线数量 |
| 增长趋势 | 20% | 品类新游发行量同比、近期爆款年龄（识别热点驱动） |
| 商业化空间 | 15% | 品类价格中位数（独游 15-50 元带）、好评率 |
| 平台匹配度 | 10% | 竞品简体中文支持率（国区是独游第一大市场） |
| 差异化空间 | 10% | 描述中的创新信号识别 |

\* 竞争强度**得分越高 = 竞争越小（越蓝海）**，与 UP 主「三步看清赛道」「深耕没人抢的空缺赛道（《放置之路》案例）」的方法论一致。

**每个维度带状态标注**：✅ 数据充足 ｜ ⚠️ 部分数据 ｜ ❌ 无数据（按中性 50 分计入）｜ ➖ 无显著信号（分析已跑但没发现信号）——报告中的「数据缺口说明」会明确列出缺的是哪些数据、可能原因（接口限流/标签未匹配/样本窗口不足），与「系统没数据」和「确实没信号」区分开。

**开发周期估算**：13 类品类基准（结合 UP 主案例：幸存者like 3-8 月、休闲收纳 1.5-5 月、模拟经营 6-16 月、肉鸽卡牌 10-22 月、3D 动作 24-48 月…）× 维度/范围/团队效率/经验系数 → 乐观/基准/悲观三档 + Demo/EA/1.0 里程碑 + 三条路线（MVP 试水 / EA 均衡 / 完整打磨）。

**上线窗口评级（优/良/险/闭）**：品类动量（上升期 24 月 / 平稳 15 月 / 热点驱动 12 月 / 衰退 9 月）对比基准工期，叠加即将上线竞品密度修正。市场未来不可预测 → 报告给出**乐观/中性/悲观情景预案**与**季度检查信号**（新游量、头部在线、爆款数、愿望单转化），支持滚动复查决策。

**评估过程可视化**：全程显示「第 X/4 步」进度横幅与耗时；推理模型（deepseek-flash/reasoner）的思考过程实时流式展示（可折叠），不再"看起来卡住"。

## 🧬 学习进化机制

1. **观点沉淀**：每次调研/对话的结论自动提炼为洞察（去重、加权）入库；
2. **周期复盘**：每日快照 Steam 热销榜并对比、检索行业新闻、同步 UP 主新视频，LLM 生成复盘要点入库；
3. **自动调研队列**：复盘后 LLM 自动提出 2 个值得深挖的问题，调度器每天限量自动执行并沉淀结论；
4. **反馈学习**：👍👎 反馈入库，用于后续检索与复盘参考；
5. **项目档案**：每次评估自动建档，随时问「回顾项目 X 的评估结论」。

## ❓ 常见问题

- **B 站接口被风控？** 已内置 wbi 签名、浏览器指纹头、限速与自动重试；若持续被拦，稍等几小时再跑，或只影响视频字幕抓取（不影响 Steam 数据）。
- **不想用 DeepSeek？** 任意 OpenAI 兼容服务均可：改 `.env` 的 `LLM_BASE_URL` / `LLM_MODEL`（如通义、智谱、Kimi、本地 Ollama `http://127.0.0.1:11434/v1`）。
- **SteamSpy/SteamDB 被 Cloudflare 拦截？** 本工具默认**不依赖**它们（用 Steam 官方接口 + 搜索页 + SteamCharts）。想额外要销量/拥有者数据，可接第三方付费 API（见上文「可选：接第三方 / 付费数据源」）；SteamDB 自己封爬虫与你无关，别把它的验证页怪到本工具头上。
- **数据源填了 key 却报「调用失败」？** 看提示原因：Cloudflare 人机验证 = 该源不让服务器直连；401/403 = key 无效或额度用尽；不是 JSON = URL 模板/路径不对。评估不会因此中断，只是回到官方数据。
- **重置知识库？** 停服后删除 `data/` 目录，重新播种即可。
