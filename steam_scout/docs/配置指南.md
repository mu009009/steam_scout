# 配置指南（分享给他人时可直接发这一篇）

## 一句话结论

**只需一个大模型 API Key**。Steam 商店数据、SteamCharts 在线人数、B 站视频、Bing 搜索全部是公开接口，**不需要任何其它 Key**。

## 方式一：网页里填（推荐，零门槛）

1. 双击 `start.bat`（或 `node server.mjs`），打开 `http://127.0.0.1:8792`
2. 左侧状态卡点「⚙️ 配置 LLM API」
3. 填三项：
   - **API Key**：你的 key（`sk-...`）
   - **服务地址**：默认 `https://api.deepseek.com`
   - **模型名**：`deepseek-chat` 或 `deepseek-flash`
4. 点「保存并测试」→ 通过后会写回 `.env` 并立即生效（无需重启）

> 未配置时页面会自动弹出这个向导。

## 方式二：编辑 `.env` 文件

复制 `.env.example` 为 `.env`，填：

```ini
DEEPSEEK_API_KEY=sk-你的key
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
PORT=8792
```

保存后重启（`start.bat`）。

## 方式三：环境变量

```bat
set DEEPSEEK_API_KEY=sk-xxx
start.bat
```

## 支持哪些模型服务

任何 **OpenAI 兼容** `/chat/completions` 接口都可以：

| 服务 | Base URL | 模型示例 |
|---|---|---|
| DeepSeek（推荐） | `https://api.deepseek.com` | `deepseek-chat` / `deepseek-flash` / `deepseek-reasoner` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| SiliconFlow | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-7B-Instruct` |
| 本地 Ollama（完全离线） | `http://127.0.0.1:11434/v1` | `qwen2.5:7b`（Key 随便填非空值） |

> 推理型模型（如 `deepseek-flash`、`deepseek-reasoner`）会先"思考"再回答，已在内部做了兼容（流式正文为空时自动回退）。

## 怎么验证配置成功

- 页面左侧状态显示 **「LLM 已配置 · 全功能可用」**（绿点）
- 或访问 `http://127.0.0.1:8792/api/health`，返回 `{"ok":true,"llm":true}`
- 或发一句「你好」能正常回复

## 不配 LLM 能用吗

可以，但只有**离线部分**：
- ✅ 立项评估（评分引擎 + Steam 数据采集）、知识库检索、项目档案、数据盘点、市场复盘快照
- ❌ 对话推理、专家解读、观点提炼（这些需要大模型）

## 隐私说明

- API Key 只写在本机 `.env` 文件里，不会上传到任何第三方服务（除了你自己的模型服务商）
- 分享项目时**不要带 `.env`**（`打包分享.bat` 会自动排除它；分享包内的数据库也已脱敏，不含你的对话与项目档案）

## 可选：接第三方 / 付费数据源（补充销量·拥有者·在线）

默认**不接**任何付费源：只用 Steam 官方接口 + SteamCharts，一分钱不花。

如果你买了第三方的 Steam 数据服务（能给出销量/收入/拥有者估算），可以在
「⚙️ 配置 LLM API → 🔌 可选：第三方 / 付费数据源」里选源并填 Key，
或直接在 `.env` 里写：

```ini
DATA_PROVIDER=gamalytic
DATA_PROVIDER_KEY=你的key
DATA_PROVIDER_URL=
DATA_PROVIDER_MAP=
```

> 可选值只有 4 个：`steamapi`（免费）/ `steamspy`（免费但常被拦）/ `gamalytic`（付费）/ `custom`（自己接）。
> 为什么没有 VG Insights 和 Steambase：见下方「已确认不能用的」。

### 「选哪个源，就用哪个源的数据」

评估流程是这样的：**官方接口优先，缺什么才用你选的源补什么**。

| 数据 | 来源优先级 |
|---|---|
| 价格 / 好评率 / 是否支持中文 / 发行日期 | Steam 官方商店接口（永远优先） |
| 24h 在线峰值 | SteamCharts → 缺失时用所选数据源 |
| 评价数 | Steam 官方评价接口 → 缺失时用所选数据源 |
| 拥有者 / 销量近似 / 收入估算 | **只有你选的数据源能给**（Steam 官方不公开） |

报告首页会写明本次用了哪个补充源，例如
`数据来源：Steam 商店实时数据 / SteamCharts / 网络检索 / 本地知识库 / 补充数据源 Gamalytic`，
并在下方注明「官方接口缺失的估算字段由「Gamalytic」补充；价格、好评率等仍以 Steam 官方接口为准」。
第三方的数字不覆盖官方数字，只填空缺——避免不同口径混在一起算出怪结论。

### 内置可选源（2026-11 逐个实测过，不是抄来的清单）

| 值 | 名称 | 需要 Key | 能不能真用上 | 说明 |
|---|---|---|---|---|
| （空） | 不接任何源 | 否 | ✅ **最省事，推荐** | 只用 Steam 官方商店接口 + SteamCharts + **官方在线人数兜底**（见下），一分钱不花 |
| `steamapi` | Steam 官方 Web API | 否 | ✅ **实测可用** | 实测 200 返回 `player_count`。现在**已内置到默认流程**，不用选也能享受在线人数兜底 |
| `gamalytic` | Gamalytic | 是 | ✅ **接口真实存在** | 无 Key 访问 `api.gamalytic.com/game/{appid}` 返回 403 "This endpoint requires an API key"（说明接口与路径正确，只差 Key）。是目前唯一**公开价格 + 公开误差研究**的 Steam 销量估算商 |
| `custom` | 自定义 | 看你接的 | ✅ 任意 JSON 接口 | 填 URL 模板 + 字段映射，可接 Apify 抓取器、公司内部服务、自建代理 |

**已确认不能用的（别再找了）**：

| 名字 | 结论 |
|---|---|
| **SteamSpy** | 免费、不用 Key，但 2026-11 实测：**不管换什么请求头/Referer/XHR 标识，`steamspy.com/api.php` 一律返回 Cloudflare 人机验证页（HTTP 403 challenge）**，程序拿不到数据。已从下拉里隐藏；如你想再试，可用 `custom` 填它的 URL。 |
| **Steambase** | 只有面向玩家的网站（排行榜/价格历史/评价趋势）和 Discord、Slack 机器人，**没有公开数据 API**。`api.steambase.io` 是猜的，实查 404。 |
| **VG Insights** | 已被 **Sensor Tower** 收购，`vginsights.com` 现在跳转 `app.sensortower.com/vgi`，`api.vginsights.com` 无法解析；只剩企业版 API，需联系商务询价（无公开价）。 |
| **SteamDB** | 没有任何官方 API，且明确反爬。**本工具从不访问它**；你在浏览器里手动刷 SteamDB 触发的封禁与本工具无关。 |

### 免费方案（不用花任何钱）到底能拿到什么

工具默认（不接第三方源）就已经在免费地拿这些：

| 数据 | 免费来源 | 备注 |
|---|---|---|
| 价格 / 好评率 / 是否支持中文 / 发行日期 / 标签 | Steam 官方商店接口 | 最权威 |
| 评价数 | Steam 官方评价接口 | 用来 `评价数 × 35 ≈ 销量`（Boxleiter 法） |
| 24h 在线峰值 | SteamCharts 网页 | 偶尔会抽风 |
| **当前在线人数** | **Steam 官方 `GetNumberOfCurrentPlayers`（免 Key）** | 2026-11 新增：SteamCharts 拿不到时自动兜底，按保守下界计入 |
| 品类新游密度 / 即将上线数量 / 热销榜 | Steam 商店搜索页 | 竞争强度、趋势判断的主力 |
| 行业趋势、案例热度 | Bing 搜索 + B 站 | 定性参考 |

> 换句话说：**「评价数×35 + 在线人数 + 新游密度」三件套，免费且够看量级**。付费源（Gamalytic）的价值是把畅销榜排名、在线曲线、区域定价混进来再修正——是"更准"，不是"从无到有"。

### 怎么拿到 Key（按需选一个）

**A. 免费（推荐先走这条）：什么都不用填**
- 官方在线人数接口本身免 Key，已在默认流程里
- 如果哪天想用 Steam 其它官方接口（玩家资料等），Key 在 https://steamcommunity.com/dev/apikey 申请。
  ⚠️ 该页面要求 **账号在 Steam 上消费满 5 美元**，否则会提示没有权限——这不是本工具的限制。**本工具的功能一个都不需要那把 Key。**

**B. Gamalytic（要销量/收入估算就选它）**
1. 打开 https://gamalytic.com/ 注册账号（有免费档，可以先试网页数据）
2. 想要 API 需要订阅：**Starter $25/月（含 2,500 次/天 API）** 或 **Professional $75/月（完整 API）**，30 天可退款
3. 订阅后在控制台/账户页复制 API Key（形如一串随机字符）
4. 回到本工具「⚙️ 配置 LLM API → 🔌 第三方 / 付费数据源」→ 数据源选 `Gamalytic` → 粘贴 Key → 「保存并测试数据源」
   （测试会真的打一次 `appid 413150`（星露谷）；成功会显示「拥有者/销量估算」等字段）
5. 它的误差是自评 **77% 的估计落在真实值 ±30% 内、98% 在 ±50% 内** —— 所以在报告里当**区间**用，别当精确财报

**C. 自定义（有 Apify / 自建服务 / 公司数据就用这个）**
- Apify 上的 Steam 抓取器：注册后有个人 token，跑一个 actor 的同步接口形如
  `https://api.apify.com/v2/acts/<actor>/run-sync-get-dataset-items?token=<token>`，
  但每个 actor 返回结构不同，需要用 `DATA_PROVIDER_MAP` 映射。这类方案是**按次计费**，比订阅灵活。

自定义示例（把任意 JSON 接口映射成我们的字段）：

```ini
DATA_PROVIDER=custom
DATA_PROVIDER_URL=https://your-api.example.com/game/{appid}
DATA_PROVIDER_KEY=xxx
DATA_PROVIDER_MAP={"reviews":"reviews.total","positivePct":"reviews.score","owners":"owners","peak24h":"ccu"}
```

- `{appid}` / `{name}` 会被替换成 Steam appid / 游戏名
- 字段映射是「我们的字段: 对方 JSON 的路径」，路径用点号往下取
- 鉴权：Key 会**同时**放在 query（`?apiKey=…`，参数名可用 `DATA_PROVIDER_KEY_PARAM` 改）和 `Authorization: Bearer` 头里，两类服务都能兼容；可用 `DATA_PROVIDER_AUTH_HEADER` / `DATA_PROVIDER_AUTH_PREFIX` 覆盖

### 数据源挂了会怎样

不会阻塞评估：调用失败只在过程中提示一行
`⚠️ 数据源 X 调用失败（HTTP 403：This endpoint requires an API key…），继续用官方接口数据`，然后照常用官方数据出报告（对应维度会记入「数据缺口说明」）。
Key 无效/额度用尽也走这条路，不影响其他功能。

> 提醒：想省钱的替代办法——本工具自带的 `评价数 × 35 ≈ 销量`（Boxleiter 法）本来就是免费估算，付费源的价值是把它和「畅销榜排名 + 在线人数曲线 + 区域定价」混合后再修正。决策时把数字当**区间**看，别当精确值。
